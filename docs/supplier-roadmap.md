# B2B и подтверждённая экономика: этапы

## 1–2. Каталог поставщиков и синхронизация — реализованы в коде

Подробности, лимиты, безопасность и расписание — `docs/supplier-sources.md`.

- Регистрация с выбором типа аккаунта: «Участвую в тендерах» / «Поставляю товары» (`account_access`, не роль администратора).
- `/supplier`: Excel/CSV с сопоставлением колонок, XML по ссылке (YML, Kaspi-подобный), 1С OData и REST-контракт.
- Конвейер fetch → parse → normalize → validate → diff → commit; ошибки не обнуляют каталог.
- Заявки поставщику с согласиями сторон, без комиссий.

### Запуск

1. Применить `supabase/migrations/0009_supplier_sources.sql` (после 0008) через обычный процесс миграций.
2. Для XML/1С: `SUPABASE_SECRET_KEY`, `SUPPLIER_SOURCES_ENC_KEY` (`openssl rand -base64 32`), `CRON_SECRET`.
3. Для обновления чаще раза в сутки — внешний планировщик и `SUPPLIER_SYNC_SCHEDULER_INTERVAL_MINUTES`.

Команды: `npm test`, `npx tsc --noEmit`, `npm run build`, при запущенном сервере — `npm run test:catalog:e2e`.
Шаблоны: `npm run samples:gen` → `public/samples/supplier-price-template.{xlsx,csv}`.

## 3. Техническое соответствие и заявки

Сопоставлять точную модель, паспорт и требования ТЗ; цитаты и страницы.
Матрица: соответствует / не соответствует / неизвестно. Неизвестное не означает соответствие.
Запрос предложения на партию: цена, НДС, наличие, предоплата, доставка, гарантия, срок действия.
Резервирование только после ответа поставщика. Реклама отдельно от ранжирования по соответствию.
Лиды и комиссия — только после согласования договора и способа подтверждения сделки.

## 4. Финансовый профиль

Регистрационные сведения отдельно от финансовой верификации.
Импорт отчёта учёта с подтверждением пользователя: деньги, обязательства, поступления, другие контракты.
Доступ к 1С/банку по разрешению, с минимальными правами. Не собирать пароли банка/eGov или закрытые ключи ЭЦП.
Не считать общий банковский остаток свободным капиталом. Не вычислять прибыль по БИН.
Версии данных и допущений, отдельные права доступа, удаление и политика хранения.

## 5. План / факт и пилот

Выбрать одну категорию, привлечь поставщиков и покупателей.
Проверить извлечение критических полей экспертами и сравнить с исполненными контрактами.
Измерять ошибки, время проверки, повторное использование и реальные платежи.
Дообучение модели — после накопления согласованного датасета и сравнительного теста, не вместо проверки данных.
