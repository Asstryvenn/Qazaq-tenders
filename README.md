# Qazaq Tenders

Экономический симулятор участия МСБ в госзакупках РК.

```bash
npm install
npm run dev   # http://localhost:3077
```

## Архитектура

- `lib/types.ts` — строгий JSON-контракт. `TenderSpec` — единственное, что заполняет AI-слой.
- `lib/engine.ts` — детерминированный движок: Π, M_rel, посуточный CF_t, L_score, R_legal, TOS.
  Ни LLM, ни случайностей: одинаковый вход → одинаковый выход.
- `lib/mock-data.ts` — мок-база лотов + цифровой двойник компании. Заменяется адаптером
  над zakup.gov.kz без изменений в движке.
- `app/page.tsx` — лендинг, `app/dashboard/page.tsx` — дашборд.

## Отклонения от исходной спецификации (осознанные)

1. **`marginScore` нормирована.** В формуле TOS `w1 · M_rel` даёт при марже 15% всего 15 баллов
   из 35 возможных, из-за чего почти любой реальный лот проваливается. Маржа приводится к шкале
   0–100 относительно `TARGET_MARGIN_PCT = 20`. Форма формулы и веса не тронуты.
2. **`opexAllocation`.** Компания ведёт несколько контрактов параллельно, поэтому на один лот
   относится доля накладных (по умолчанию 0.35), а не весь месячный OPEX.
3. **Цвет вердикта.** Бейдж и гейдж окрашиваются по `verdict`, а не по «сырому» TOS — иначе лот
   с кассовым разрывом мог бы отображаться зелёным.
4. **`C_bank` считается в два прохода**: первая симуляция находит дни отрицательного баланса,
   по ним начисляются проценты кредитной линии, вторая симуляция учитывает их как отток.
